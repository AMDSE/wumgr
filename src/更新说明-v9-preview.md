# v9 预览版：更清晰的驱动工作台

这轮先优化日常操作和内部重复计算，不为换代引入大型运行时。保留 v8 的设备清单、中英文、历史候选、多线程下载、可选静默安装及可恢复驱动更新保护。本版为本地预览，未替换 GitHub 已发布的 v8。

## 界面怎么变了

分类从横排改为固定侧栏，设备搜索、驱动更新保护和许可入口更容易找到。主工作区独立展示摘要、搜索和设备卡片，保存目录、安装选项、下载和取消操作保留在底部，不随设备列表滚走。

默认工作区为 1280×860，启动会按屏幕可用空间收缩。新版用表格布局分配空间，支持更小窗口；长文本采用省略号，完整硬件信息仍可从“详情”读取。历史版本列按比例分配，不再依赖只适合大窗口的固定位置。没有更新候选的设备继续显示已安装信息，不伪报“最新版”。

快捷键：**Ctrl+F** 聚焦搜索，搜索框中按 **Escape** 清空，空闲正式模式下按 **F5** 扫描。演示模式继续禁止真实扫描、下载、安装和策略修改。

## 内部做了什么

数据重建与纯界面筛选分离：只有设备／候选清单变化时才重建匹配结果。搜索、分类和语言切换复用已匹配设备快照，不再在每次输入时重复执行整套硬件匹配。设备列表启用双缓冲；卡片绘制复用字体，在卡片销毁时释放，减少滚动重绘时临时 GDI 对象的分配。

设备清单构建时，每个设备只建立一次硬件 ID 集合供排序使用。候选规范化时，单次调用内缓存有效 URL 集合，避免在 revision 和载荷去重时重复解析。没有扩大硬件匹配范围、放宽下载 URL 校验，或把不同载荷的同版本错误合并。

## 同时修复的边界问题

独立审查发现缺少 WUA 更新 ID 的候选可能共用空选择键，导致不同设备或历史候选串选。本版为这些候选分配仅在当前窗体内使用的独立选择键，历史单选按候选对象身份判断；不会篡改系统更新 ID，也不会让缺少有效更新身份的项目绕过安装器检查。新增测试覆盖独立勾选、计数、历史选择及搜索／语言切换后的保持。

英文模式的扫描开始状态、退出确认和策略确认／恢复对话框补齐显示层翻译，不修改原始业务状态。

## 为什么暂时不整体迁移框架

目前继续使用原生 **WinForms + .NET Framework 4.8**，与已有 Windows 10／11、WUA 和 SetupAPI 实现衔接，避免为了新界面捆绑浏览器内核或大型自包含运行时。不是拒绝后续迁移，而是先建立回归保护，再按 Windows 实机结果决定是否值得更换技术栈。

构建仍为 AnyCPU、非自动提权。DPI 模式仍是系统 DPI 感知：这轮调整新建卡片的缩放与布局，但**没有宣称已支持动态每显示器 DPI**。不同缩放显示器间移动后，建议按目标屏幕重新启动；125%／150%／200% 和真实 Windows 字体仍须验收。

## 5MB 怎么计算

打包脚本对**完整程序目录**和**包含源码、许可、预览与测试日志的 ZIP**分别执行 5,000,000 字节上限检查；超限即失败。系统预装的 .NET Framework 4.8 不随包分发，不计作应用体积。没有为缩小体积删除对应源码、许可证或安全校验。

运行方式不变：Windows 10／11，解压后运行 `程序\wumgr.exe`。默认仅下载；需要安装或修改保护策略时才以管理员权限运行。

## 验证到哪一步

新增双语多尺寸布局测试、键盘测试、快照复用测试和合成设备／候选性能样本，随 `tests/run-tests.sh` 运行。既有设备枚举、候选去重、下载与断点、安装取消、策略备份恢复和语言切换测试继续执行。具体结果以包内自动化日志为准；合成性能计时只用于同机回归，不等于 Windows 实机提速承诺。

所有程序预览来自 Linux／Mono 的真实窗体与演示数据，不是设计稿，也不是 Windows 实机扫描结果。**Windows 更新服务、微软 CDN、真实设备安装、策略生效与高 DPI 实机验收尚未完成**，详见 `tests/Windows验收清单.md`。本轮未对当前环境执行真实驱动安装或策略变更。
