# v7：设备识别与重复驱动修复

## 修复了什么

- 主界面改为以真实本机设备为准。显卡、声卡、网卡、蓝牙、系统设备和其他设备即使没有 Windows Update 候选，也会保留在设备清单中，不再把“没有更新”显示成“没有识别”。
- 新增 Windows 原生 SetupAPI 全类别、当前存在设备枚举，读取实例 ID、完整硬件 ID、兼容 ID、类别 GUID、设备状态和已安装版本；WMI 作为补充和回退。版本查询或个别属性失败不再中断整张设备清单。
- 按设备实例 ID 合并枚举记录，而不是按名字合并。两张同型号网卡仍是两台设备；未知设备和缺驱动设备也保留。
- 用 PnP 类别和安装类 GUID 分类，新增蓝牙、系统设备独立页签。不会因厂商是 Intel、AMD 或设备名包含 CPU 字样，就把其他硬件误归为芯片组。
- 同一更新 ID 只保留最高修订；不同 ID 但硬件集合、版本、日期、元数据及下载包相同的候选合并。保留不同版本、不同硬件和不同下载包，不把真正的历史版本误删为重复。
- 不混合不同修订的下载文件。移除逐候选执行整机 WMI 型号查询，避免反复枚举造成的额外开销。
- 即使 Windows Update 查询失败，已经读取的本机设备清单仍然可查看；无匹配候选卡片不会产生虚构驱动，也不能下载或安装。

## 使用方法

解压修正版，运行 `程序\wumgr.exe`，点击“扫描设备驱动”。设备没有可用候选时会显示已安装版本或“未提供”，以及“当前更新源无匹配候选”。可在分类页签或“设备搜索”查看硬件 ID。

中英文切换、历史候选、多线程下载、可选静默安装和可恢复的驱动更新保护均保留。默认只下载，不安装、不自动重启。源代码随程序提供。

## 已验证和仍需确认的部分

已在 Linux/Mono 上构建并运行自动化回归，包含真实 WinForms 控件测试、设备清单合并、六类设备无更新仍显示、60 条同包候选合并、历史版本保留、修订号、原生接口布局和属性常量等；完整结果随发布包附带。

这些测试不等于 Windows 实机硬件测试。当前环境无法验证你的显卡、网卡等真实硬件、Windows WMI/SetupAPI 返回值或 Windows Update 实际推送结果。Windows 10/11 + .NET Framework 4.8 实机验收仍需进行。Mono 构建器会提示其旧工具集未正式支持 v4.8，这一限制不应被当成 Windows 构建验证。

设备识别和可下载更新是两回事。更新候选仍仅来自系统当前配置的 Windows 更新服务，受网络、组织策略、更新源和厂商分发范围影响，不保证提供每个设备的驱动或所有历史版本，也不保证提供厂商最新驱动。未能按完整硬件 ID/兼容 ID 匹配的候选不会强行关联设备。
