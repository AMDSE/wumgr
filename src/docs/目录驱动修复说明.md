# Microsoft Update Catalog 驱动搜索修复

本次只修改 WinForms V8 与 V10，不修改独立 WPF Preview 2。旧版标签与旧包保留，新增补丁版分别为 8.0.1 与 10.0.1 Preview。

## 使用变化

默认仍先查询 Windows Update Agent（WUA）。WUA 查询失败或未返回候选时，使用本机具体硬件 ID 查询 Microsoft Update Catalog；勾选历史搜索时也补充目录候选。在“设备搜索”选定设备后，可主动搜索微软目录、逐步扩大翻页范围。网络失败、查询预算或翻页上限不等于“设备没有驱动”。

目录搜索命中后，还会读取详情中的真实硬件 / 兼容 ID，与本机完整 ID 核对；不会把搜索词写成驱动硬件 ID。产品、架构和目录链接用于人工核对，不会把硬件匹配宣传为完整系统适用性验证。目录结果不是完整版本历史，也不是安装推荐。

下载时才解析微软目录的真实包链接，允许全部合法包链接，限制为微软官方 HTTPS 下载域，逐跳检查重定向，保留既有分块、取消、条件续传和原子落盘。目录当前包的修订号不等于 WUA 返回的特定修订；说明文件会记录来源。下载目录的文件不会被直接执行。

## 安装边界

默认仅下载。目录来源不会进入自动下载选择。目录来源只允许下载，安装入口拒绝它冒充 WUA 适用更新；混合批次也会明确提示全部仅下载。只有单独选择 WUA 候选主动安装时，才会要求管理员权限与确认，由 WUA 重新查询身份、精确修订与适用性、确认 EULA 状态，再使用系统缓存安装。程序不会强制安装目录包、绕过签名、自动重启或执行本地 EXE/CAB。

## 运行

Windows 10 / 11 + .NET Framework 4.8。完整解压后运行 `程序/wumgr.exe`，保留同目录 Downloader.dll 与配置。V8 保留原界面；V10 保留现代工作区。程序未作代码签名，不能以本次测试代替可恢复 Windows 测试机验收。

## 验证与已知限制

包内附对应源码、测试和本轮日志。Linux/Mono 回归及微软目录在线协议验证不等于 Windows 实机上的 SetupAPI/WMI/WUA、管理员安装、策略、高 DPI 验收。微软目录网页不是稳定公开 API；结构变化会明确报错，不会伪装为空结果。检索有预算与翻页限制，可在设备搜索中继续扩大；目录本身存在返回数量上限。

官方说明：[Catalog FAQ](https://www.catalog.update.microsoft.com/faq.aspx) 支持硬件 ID、型号、厂商检索；[微软手动下载指南](https://learn.microsoft.com/en-us/troubleshoot/windows-client/installing-updates-features-roles/download-updates-drivers-hotfixes-windows-update-catalog)。Windows Update Agent 与目录网站是不同入口，不能将系统更新机制简单等同于抓取目录网页。
