# WPF 实现的关键取舍

## 真正换界面，不同时重写驱动引擎

`WuMgr.Wpf` 使用 XAML 和 WPF 原生控件，没有 `WindowsFormsHost`，也没有引用 `System.Windows.Forms`。`WuMgr.Core` 以链接源码方式复用 V10 的设备枚举、候选规范化、下载器、WUA 安装和保护策略。原始业务文件不为换界面而复制修改两套，避免已有修订号、续传、路径和恢复安全规则在迁移中分叉。

应用仍目标 .NET Framework 4.8。这样可复用原核心及 Windows COM 互操作，不要求用户为了看预览额外安装新的 .NET 桌面运行时。开发时用现代 .NET SDK 和固定版本的参考程序集包进行可复现编译；这不意味着 WPF 能在 Linux 运行。没有为了减少几个属性而再引入第三方 MVVM 框架。

## 两条接口隔离真实系统和界面交互

`IBackend` 封装 SetupAPI/WMI、WUA、下载、安装、管理员身份和策略；`IInteraction` 封装确认、目录选择、打开目录、语言保存与详情窗口。视图模型不直接调用 MessageBox、Explorer、注册表或 WUA COM。

真正的后台异步放在适配器与原核心里，VM 的 await 保留 UI 同步上下文。构造时要求有同步上下文；应用启动显式使用 DispatcherSynchronizationContext。无界面回归使用单线程消息泵，因此不仅能断言计数，还能检查所有交互是否回到了 UI 线程。

## 一个任务拥有一次操作的全部生命周期

协调层在开始时创建独立 CTS，固定操作标识，先标记 busy，再让任务进入异步执行；实际任务返回前不释放 CTS、不恢复 idle。所有命令除 CanExecute 外仍在执行体检查 disposed、busy 或 demo，直接调用 Execute 也不能绕过这些边界。

`WaitForIdleAsync` 只等待，取消由 `Cancel` 明确发出。窗口忙碌关闭时取消、禁用窗口、等待真实结束后再排队关闭；空闲关闭不递归触发 Closing。生命周期 Dispose 幂等，忙碌时延迟释放。带操作标识的进度回调会丢弃已结束或旧任务的消息，避免迟到进度覆盖最终结果。

下载前固定所选 DriverInfo 集合、目录和安装选项，按 UpdateID＋RevisionNumber 去重。无身份候选不会因为空字符串键而被误合并。下载失败不等于全部失败：只把 `DriverInstaller.HasDownloadedPackage` 明确确认的成功项交给独立安装确认。取消发生在安装以后，展示实际完成数、失败、错误与重启要求，不宣称回滚或未安装。

## 显示状态与原始元数据分开

原始硬件标识、供应商、驱动名称、UpdateID 和版本保持不变。标签通过索引器通知切换；状态、进度和日志在显示层复用 V10 的短语翻译，加上 WPF 自己的确认与边界说明。类别对象支持属性通知，切换语言不丢类别 Key。行实例在文本/类别筛选时保留，选择不会随视图隐藏而被悄悄清除。

候选精确匹配和自动选择沿用核心规则；版本显示额外保留直接硬件匹配优先、数字版本和日期排序，而不是字符串字典序。“自动选择”不等于自动安装或安全认证。

## 布局和系统适配尽量保持原生

主设备 ListBox 在有限高度中虚拟化，卡片内版本列表限制高度并独立虚拟化；不使用外层无限 ScrollViewer 破坏虚拟化。搜索延迟 180ms；进度最多约每 100ms 更新，日志保留最后 20,000 个字符。底栏分路径、选项、进度和日志，不使用会无限扩宽的单行 StackPanel。

自定义样式只替换视觉模板，保留 Button、CheckBox、ListBox 的键盘和选择语义；关键入口提供 Automation 名称。目录选择用 Windows Common Item Dialog，明确释放 COM 对象，不为了一个目录选择器引入 WinForms。

## 验证分三层，结果不混用

1. V10 核心/原界面：原有 263 项断言日志单独保留，原业务源未改。
2. 新 WPF 协调层：82 项有意义的可控后台断言，覆盖错误、拒绝、部分成功、权限、未完成后台、取消后结果、进度和 UI 线程。
3. Windows 原生 WPF：已提供并编译 `WuMgr.Wpf.Smoke`，真正创建窗口、检查运行时绑定、切换语言/尺寸、生成实际 WPF 渲染截图；本次没有 Windows，尚未执行。

高 DPI、辅助功能、真实设备/WUA、策略写入和真实驱动安装属于第三层及实机验收范围，不由 Linux 编译或假后台测试替代。这个边界就是当前交付明确标为预览而非稳定发布的原因。


## Preview 2：原生启动链

`Bootstrapper` 使用原生 Win32 C，输出 `WuMgr.exe`，不引用 CLR；通过注册表检测 .NET Framework 4.8+。环境缺失时使用微软 HTTPS 离线安装包、验证发布者签名、单独提权安装，并按退出码处理重启和失败；主程序入口 `WuMgr.Wpf.exe` 以及现有 MVVM / 核心业务保持不变。包不内置百兆运行时。具体说明见 `RUNTIME-BOOTSTRAP.zh-CN.md`。
