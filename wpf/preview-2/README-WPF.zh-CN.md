# WuMgr WPF Preview 2

这是一套真正的 Windows WPF 界面，不是套在 WPF 窗口里的 WinForms，也不是网页原型。使用 XAML、原生 WPF 控件和 MVVM 协调层，共享 V10 已有的驱动业务核心。它与 WinForms V10 独立运行，不覆盖 V10。

**当前定位：可运行的源码对应预览版，不是已经通过 Windows 实机验收的稳定版。** 已完成 .NET Framework 4.8 交叉编译和 82 项可控后台逻辑回归；当前环境没有 Windows，不能把这些结果当成实际 WPF 渲染、Windows Update 安装或高 DPI 验收。没有用设计图冒充程序截图。

## 先运行看看

在 Windows 10/11 上解压整个 ZIP，运行 **`程序\WuMgr.exe`**。新原生启动器自动检测 .NET Framework 4.8+；缺少时自动下载微软官方安装包、验证微软签名并请求管理员授权安装，成功后打开 WPF。需要重启时仅提示手动重启，不自动重启。首次补装约需下载 116 MiB；已有环境不下载。不要只拷走 EXE，依赖 DLL 和配置文件必须在同一目录。详见 [运行环境自动安装说明](RUNTIME-BOOTSTRAP.zh-CN.md)。

默认使用普通权限，启动只读取本机设备及保护策略，不主动启动 WUA 更新搜索。点击“扫描更新”才查询 Windows Update；默认仅下载，不安装、WPF 本身不自动提权、不自动重启。安装和修改保护策略需要用户自行以管理员身份重新打开程序，并接受对应确认。

想先看界面且不接触真实设备，可以在程序目录运行：

```powershell
.\WuMgr.exe --demo
.\WuMgr.exe --demo --lang en-US
.\WuMgr.exe --demo --lang zh-CN
```

演示数据明确标注，包含多版本、没有候选及未知设备。演示模式的真实设备扫描、下载、安装、策略、文件夹选择和打开目录均有执行体守卫；直接调用命令也不能绕过。`example.invalid` 仅是演示占位域名，不会被下载。

## 与 V10 相比，这次重新做了什么

界面改为深绿导航、暖灰画布和白色设备卡片；侧栏有常见硬件、全部设备与具体类别。1024×680 起的布局把搜索、状态、路径、进度和操作分开安排，避免底栏堆成一长排。设备列表采用虚拟化，搜索有短延迟，版本列表有独立选择和高度限制。

每张设备卡显示当前安装版本、所选候选、提供商和状态。展开候选后，每台设备选择一个版本；详情页保留原始标识、硬件 ID、候选身份及合法下载链接复制。历史只包含本轮 WUA 返回的适用候选，并不承诺完整的厂商历史版本库。没有候选不代表电脑没有驱动。

设备列表先显示，再等 WUA；WUA 失败时仍保留本机清单。刷新设备不会偷偷启动更新搜索。候选只能按完整硬件 ID／兼容 ID 匹配，不能因为显示名称相近或设备类别相同就挂到设备上。

“自动选择新版”保留原核心的保守规则：优先完整硬件匹配，排除被替代、缺乏可用下载地址或无法比较的候选，并在已安装版本可比较时拒绝选择旧版。它只选中，不自动下载或安装，不能保证新版一定更适合。未知、未安装或不可比较版本仍应人工核验。

筛选保留设备行、选择和已选版本。**清空搜索不会清空选择，隐藏的已选设备也可能进入下载。** 顶部显示全局已选数量，下载前再列出具体名称、版本、UpdateID、修订号和目录。共用更新的多台设备仍分别显示，但同一 UpdateID＋修订号只下载一次。

## 下载、安装与取消

多线程下载复用 V10 下载器的 URL、路径、重定向、文件名和续传校验。下载操作开始时固定所选版本、目录及“下载后安装”选项；忙碌时不能启动冲突操作或改动这些重要选择。

只有本轮状态确为“已下载”、且本地目录存在的项才有资格进入安装。部分失败不会把失败项或旧目录误当成成功；可用成功项仍须单独确认后才安装。

安装通过 Windows Update Agent 重新查询 UpdateID、修订号和适用性，使用系统缓存，可能再次下载；不会执行下载目录中的任意 EXE/INF，不代替用户接受 EULA，不绕过系统签名检查。可能短暂断网、闪屏或需要手动重启。安装结果保留逐项失败、日志和重启要求。

取消只是请求。COM/WUA 当前调用可能不能立即中断，窗口会等待后台真正返回再退出。取消后不继续启动安装；如果安装已发生，必须保留真实完成数量，**不会回滚已完成安装**，也不会把它描述为“什么都没做”。重复关闭不能绕过等待。

## 驱动更新保护的边界

保护只设置微软的 `ExcludeWUDriversInQualityUpdate` 全机策略，启用前备份原值；恢复时还原原值，没有备份、备份损坏或值被外部修改时拒绝盲目覆盖。不停止 Windows Update，不关闭系统安全更新。

它仅排除质量更新中的驱动，不能阻断所有驱动变化，也不能保证没有冲突。系统安全／关键更新、功能更新、首次安装、手动安装和厂商工具仍可能更改驱动；组织组策略或 MDM 可能覆盖。家庭版不承诺生效。该策略也可能影响本工具后续更新查询，需更新驱动时先恢复原设置。

## 构建和测试

源代码在 `源码` 目录。Windows 安装 .NET 8 SDK 或更新版本，并准备 x86 MinGW-w64（提供 i686-w64-mingw32-gcc） 原生编译器后运行：

```powershell
.\build-wpf.ps1
.\test-wpf-windows.ps1
```

构建输出是 `dist\WuMgr-WPF`。解决方案包含共享核心、WPF 主程序、无界面逻辑回归和 Windows 真界面冒烟测试。应用本身目标仍为 .NET Framework 4.8，SDK 仅用于开发构建。

Linux 的逻辑测试也可执行 `bash tests/run-vm-tests.sh`，需要 .NET SDK、Mono 和 mcs。测试使用可控假后台和单线程 UI 同步上下文，不会访问真实 Windows 驱动、网络下载或注册表。

82 项回归实际覆盖设备先显示、常见/全部分类、精确匹配、数字版本排序、无 URL 选择守卫、语言切换、命令通知、WUA 失败保留清单、无管理员仅下载、部分失败、独立安装确认、具体项确认、取消等待、忙时防重入、忽略取消的后台、安装后取消保留结果、迟到进度、策略权限/备份/拒绝确认和初始化等待等。原 V10 的 263 项日志另外提供，不能与 WPF 真界面验收混为一谈。

## Windows 真界面验收怎么做

ZIP 中 `验收工具` 提供已编译工具，运行 `运行安全验收.cmd`，无需 SDK。也可从源码执行 `test-wpf-windows.ps1`。它只使用演示数据，检查实际 WPF 绑定、搜索、语言切换、选择通知、按钮可见性，并生成中英文宽/窄窗口和详情图及 `RESULT.txt`。这套工具已编译，但本次尚未在 Windows 执行，包中没有伪造 PASS 或伪造运行截图。

仍需在 Windows 验收：100%／125%／150%／200% 缩放、多屏切换、键盘/屏幕阅读器体验、真实 SetupAPI/WMI 枚举、WUA 返回和网络异常、管理员保护启用/恢复，以及实际签名驱动安装。涉及安装与策略写入时应在可恢复的测试机或虚拟机中执行，不应拿主力电脑做首次验收。

快捷键：`F5` 扫描更新，`Ctrl+F` 搜索，搜索框内 `Esc` 清空。语言保存在 `%LOCALAPPDATA%\WuMgr\language.txt`。启动器和 WPF 预览程序本身没有 Authenticode 签名（下载的微软安装包必须通过签名验证）；如被安全软件拦截，不建议关闭防护来绕过。
